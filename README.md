# DSHA

A phone UI for **dsh**, a DeepSeek-powered coding/ops agent that runs on your own phone in Termux, with your files and shell.

```
DSHA (Android, WebView UI) ──HTTP+SSE, bearer token──▶ dsh (Node, Termux, 127.0.0.1:8787) ──▶ api.deepseek.com
                                                         └─ tools: bash, read/write/edit file, list, grep, glob, web_fetch, todo, + MCP servers from ~/.dsh/mcp.json
```

## Use
1. In Termux: `dsh key` (or put the key in `~/.config/deepseek/key`), then `dsh start`.
2. Open DSHA → **Pair with Termux**. The app runs `dsh start && dsh token` through Termux's RUN_COMMAND (needs `allow-external-apps = true` in `~/.termux/termux.properties`, and Android asks once for the permission). You can also paste the URL and `dsh token` output in Settings.
3. Chat. Tool calls show as cards; in **Ask** mode, shell, edits and web fetches wait for Allow / Always / Deny. **Edits** auto-allows file edits. **Auto** allows everything.

The terminal client shares sessions with the app: `dsh` (new session in the cwd), `dsh -c` (continue), `dsh ls`, `dsh status|start|stop|restart`, `dsh token`.

### Features
- Streams thinking (collapsible, timed), text and live tool output. Runs continue in the backend if the phone sleeps or the app closes; reopening replays the run from the event log.
- Models: `deepseek-flash` / `deepseek-v4-pro`, thinking off/low/high/max, per session. Token, cache and cost meter.
- Sessions drawer, folder picker, `/compact` (auto near 700k tokens), edit and resend a message, share transcript, share text into DSHA.
- Project instructions: `DSH.md`, `AGENTS.md` or `CLAUDE.md` in the working directory are added to the system prompt.
- Foldable-aware: unfolded, chat sits left of the hinge with an Inspector on the right (live tool output, tasks, session stats with files touched, sessions); half-folded in landscape (Flex mode), chat stays above the hinge and a control deck below has big approve/deny buttons, live output and quick actions; folded, the cover screen gets a denser single column. In the unfolded layout a top-bar button gives the chat the whole screen and hands it back. Uses the hinge-angle sensor plus the screen centre, or the Viewport Segments API when the WebView provides it.
- OLED design: true-black surfaces, hairlines and a blue-violet-cyan accent; Fraunces, DM Sans, JetBrains Mono and Space Mono bundled (Latin subsets, OFL).
- Notifications when a run finishes or needs approval while the app is in the background.

## Build & test
`./build.sh` writes `dsha.apk` (no-Gradle recipe, debug keystore). `tests/run.sh` runs the backend tests and the browser UI test.

## Security
dsh listens on 127.0.0.1 only and needs the token from `~/.dsh/config.json`. To expose it on another machine, set `host` in that file and put it behind HTTPS (the app permits cleartext only to localhost). In Auto mode the model can run any command as your Termux user.

## Changes
- 0.10.1 (17): Long runs no longer lose their start. dsh 0.6.1 trims its replay log only of finished runs, so an app reopened during a long run (every streamed token is an event, and an 18-minute run passed the 20,000 cap) replays the whole run instead of a reply's tail with no prompt. The app also reloads the session whenever a replay starts with a hole in the sequence.
- 0.10.0 (16): New mark: dsh's root node, in cobalt, forking into two lines, its subagents. The launcher, notification and agents icons are drawn from the same fork. A subagents sidebar, Claude Code style: a top-bar button (with the number still running) opens a panel from the right with the session's agents as a tree under dsh; unfolded it is the Inspector's Agents tab. Each subagent keeps one identity, its initial on a pale tint of its own hue, on its chat card, its row and its detail. The detail shows status, model, tools, tokens, the task and role, every step with its output (and Allow/Deny when one is waiting), and the report it gave dsh. Tapping an agent card in chat opens it.
- 0.9.0 (15): Subagents, Claude Code style. dsh 0.6.0 adds the `agent` tool: the main agent spawns a helper with a fresh context for one part of a task, either designed on the spot (its own role, tools and model) or a saved one by name, and gets back one report. Several in one reply run in parallel; their tool calls go through the same approval gate, their cost counts toward the session but not the context meter, and they cannot spawn further subagents. Saved definitions are Markdown files in .dsh/agents (project), ~/.dsh/agents, the presets general-purpose, explore and plan, or ~/.claude/agents (opt-in, tool names mapped). In chat, a subagent's card shows its steps nested and live, and they survive a reload; Agent setup opens on a new Subagents tab to browse, create, edit, duplicate, toggle and delete them, also as /agents.
- 0.8.1 (14): Starting a session on the unfolded screen. The drawer, and its New session button, is hidden when the Inspector is on screen, so wide mode gets its own New session button in the top bar and one in the Inspector's Sessions tab; both open the usual sheet (folder, recent folders, Start).
- 0.8.0 (13): API trouble is visible, and the web preview pane arrives. dsh 0.5.2 retries a DeepSeek call that fails before anything streams (429, 5xx, no connection, or a stream silent for 120 s) after 2, 5 and 12 s, keeps the last failure on the session, and adds `POST /api/sessions/:id/retry` plus `api` in health. The app shows the retry countdown, then a red card titled by cause (can't reach DeepSeek, overloaded, rate limited, key rejected, balance used up) with Retry, Open settings or Check balance; the card survives a reload, the run strip says Failed, and between steps it says Waiting for DeepSeek with a seconds count. On the unfolded screen, the Inspector's Preview tab shows a local dev server in a native WebView with no bridge access (http/https only), reloaded after each run. dsh can open a page there itself with the new `preview` tool (folded, the chat shows a tap-to-open line), and tapping a localhost or LAN link in a reply opens it in the pane.
- 0.7.1 (12): Sessions start in persistent storage. dsh 0.5.1 refuses temp folders ($PREFIX/tmp, $TMPDIR, /tmp, /data/local/tmp) for new sessions and the default folder, and falls back to home when the default is unusable. The app no longer inherits a temp folder for a new session or lists one under recent folders, and an older session in a temp folder shows a bar above the composer with Use home folder / Choose folder.
- 0.7.0 (11): dsh 0.5.0 ships two built-in skills. dsh-memory-evolve keeps a persistent memory in ~/.dsh/memory (one file per memory plus a MEMORY.md index that goes into every session's prompt): save, use, forget, tidy. dsh-evolve reviews sessions (new read-only `session_log` tool) for mistakes, corrections and repeated work and proposes skills, DSH.md rules or memories before writing, logging to ~/.dsh/evolve.md. App: Memory tab (view, forget, Tidy memory, Learn from session), a Built in skills group, and Use in chat on skills.
- 0.6.0 (10): Agent setup screen (drawer, Settings, or /plugins /skills /instructions) with three tabs. Plugins: add, edit, turn off/on, reconnect and remove MCP servers, and see their tools. Skills: SKILL.md folders in the project (.dsh/skills), ~/.dsh/skills and optionally ~/.claude/skills; create, view, toggle, delete; dsh 0.4.0 lists enabled skills in the prompt and loads one with the new `skill` tool. Instructions: view and edit DSH.md (new global ~/.dsh/DSH.md for every session, plus the project's), AGENTS.md, view CLAUDE.md, and see the full system prompt.
- 0.5.2 (9): Usage dashboard on the phone: tap the meter for a Usage sheet (context, DeepSeek balance, spent, speed, cache hits, tool calls, output, files). Balance also in the drawer and the Inspector's Session tab; refreshed on boot, after each run and when opened. Run strip fix: on long runs the earliest steps fold into one segment so the strip no longer spills under its label.
- 0.5.1 (8): MCP tool servers in dsh 0.3.0. `~/.dsh/mcp.json` lists servers (`command`/`args` for stdio, `url` for streamable HTTP, optional `start` hook and default `risk`); their tools join the built-ins, go through the same Ask/Edits/Auto gate, are re-listed every step (toolset gating), and each server's instructions are added to the system prompt. `dsh mcp [reload]` and `GET /api/mcp` show state. Ships configured for the Godot Editor MCP service (`godot-mcp start`, shared with Claude Code over `http://127.0.0.1:9090/mcp`). App: history cards summarise unknown tools' arguments.
