# DSHA

A phone UI for **dsh**, a DeepSeek-powered coding/ops agent that runs on your own phone in Termux, with your files and shell.

```
DSHA (Android, WebView UI) ──HTTP+SSE, bearer token──▶ dsh (Node, Termux, 127.0.0.1:8787) ──▶ api.deepseek.com
                                                         └─ tools: bash, read/write/edit file, list, grep, glob, web_fetch, todo, + MCP servers from ~/.dsh/mcp.json
```

## Use
1. In Termux: `dsh key` (or put the key in `~/.config/deepseek/key`), then `dsh start`.
2. Open DSHA → **Pair with Termux**. The app runs `dsh start && dsh token` through Termux's RUN_COMMAND (needs `allow-external-apps = true` in `~/.termux/termux.properties`, and Android asks once for the permission). You can also paste the URL and `dsh token` output in Settings.
3. Chat. Tool calls show as cards; in **Ask** mode, shell, edits and web fetches wait for Allow / Always / Deny. **Edits** auto-allows file edits. **Auto** allows everything.

The terminal client shares sessions with the app: `dsh` (new session in the cwd), `dsh -c` (continue), `dsh ls`, `dsh status|start|stop|restart`, `dsh token`.

### Features
- Streams thinking (collapsible, timed), text and live tool output. Runs continue in the backend if the phone sleeps or the app closes; reopening replays the run from the event log.
- Models: `deepseek-flash` / `deepseek-v4-pro`, thinking off/low/high/max, per session. Token, cache and cost meter.
- Sessions drawer, folder picker, `/compact` (auto near 700k tokens), edit and resend a message, share transcript, share text into DSHA.
- Project instructions: `DSH.md`, `AGENTS.md` or `CLAUDE.md` in the working directory are added to the system prompt.
- Foldable-aware: unfolded, chat sits left of the hinge with an Inspector on the right (live tool output, tasks, session stats with files touched, sessions); half-folded in landscape (Flex mode), chat stays above the hinge and a control deck below has big approve/deny buttons, live output and quick actions; folded, the cover screen gets a denser single column. In the unfolded layout a top-bar button gives the chat the whole screen and hands it back. Uses the hinge-angle sensor plus the screen centre, or the Viewport Segments API when the WebView provides it.
- OLED design: true-black surfaces, hairlines and a blue-violet-cyan accent; Fraunces, DM Sans, JetBrains Mono and Space Mono bundled (Latin subsets, OFL).
- Notifications when a run finishes or needs approval while the app is in the background.

## Build & test
`./build.sh` writes `dsha.apk` (no-Gradle recipe, debug keystore); `./build.sh standalone` writes `dsha-standalone.apk` with the bundled runtime (prepared on first build by `scripts/prepare-runtime.sh` into the git-ignored `runtime/`). `tests/run.sh` runs the backend tests and the browser UI test.

## Security
dsh listens on 127.0.0.1 only and needs the token from `~/.dsh/config.json`. To expose it on another machine, set `host` in that file and put it behind HTTPS (the app permits cleartext only to localhost). In Auto mode the model can run any command as your Termux user.

## Changes
- 0.16.1 (25): no step limit by default (`maxSteps` 0): a run goes on until it finishes, is stopped or the DeepSeek balance runs out. The Step limit choice is now No limit, 300, 1000, 3000, and it covers subagents too: they lost their own cap and now compact near the context limit like the main agent (`Runtime.digest`). A run that fails (out of credit, say) now says so in the notification instead of showing its last reply. dsh 0.11.1.
- 0.16.0 (24): long unattended runs. A Step limit choice (80, 300, 1000, 3000) in the Session and Defaults sheets sets `maxSteps`, and raising it reaches a run in progress. dsh 0.11.0 trims a live run's finished steps from the event log (the step in progress stays whole) so memory stays bounded however long a run goes; a client joining after the run's start was trimmed gets the step-level snapshot. Subagents keep their own 80-step cap (their loop has no compaction). The notification says when a run stopped at the limit.
- 0.15.1 (23): long live runs reopen correctly. The app asks dsh for a step-level snapshot (`GET /api/sessions/:id?at=step`): every finished step of the running turn arrives as stored messages and only the step in progress is replayed, instead of the whole run's token events (hundreds of thousands in a long run). Thought, reply and tool durations and the live tok/s are timed by dsh's event timestamps, so a replayed step no longer reads "Thought for 925s" or "~1044 tok/s". Messages queued during the run come back with the snapshot. The terminal client still replays the whole run. dsh 0.10.1.
- 0.15.0 (22): QA sweep (8 parallel areas, 99 findings upheld by adversarial verification, all fixed but one deferred). Highlights: mid-run auto-compaction no longer sends the app into a reload loop; Edit and resend works on messages sent in the current view; the preview tool asks like web_fetch; Edits mode auto-approves file writes only inside the session folder (not .git, dotfiles, $PREFIX or ~/.dsh); 'always allow' for an MCP tool is keyed to its server; a session left with unanswered tool calls (dsh killed mid-tool) is repaired instead of stuck; deleting a running session stops it for good; a failed save no longer crashes dsh; thinking turned on mid-run keeps DeepSeek's reasoning_content contract; Spent shows actual cost; peak windows correct under DST; usage estimates for old sessions stay on their own date; RunService stops after ~3 min of dsh unreachable and no longer races a new run; shared text isn't re-inserted after a restore and shares are capped at 100,000 chars; the terminal client handles Ctrl-C (stops the run), several approvals, reconnects after `dsh restart`, and joins a running session properly; MCP plugins: no duplicate stdio servers, HTTP re-initialises after a 404, auth headers stay with their host, editing one doesn't restart the others, a broken mcp.json is reported instead of wiped. dsh 0.10.0; tests: 90 server tests (qa-agent, qa-api, qa-tools, gate) plus PolicyCheck on the JVM.
- 0.14.0 (21): Usage page (drawer balance row, or "All sessions and total spend" in the usage sheet). Overview: total spent, last 30 and 7 days, today, balance, whether DeepSeek is at peak or off-peak now with the peak windows in local time and the share of spend at peak, daily spend for 30 days (tap a bar), spend by model. Sessions: every session (deleted ones too) by recency or spend, tap for input/cache/output/reasoning, model calls, peak spend, folder, Open session. dsh 0.9.0: every model call is appended to `~/.dsh/usage.jsonl` with what it cost at that hour (peak 01-04 and 06-10 UTC on weekdays; `isPeak()` in deepseek.mjs), sessions gain `usage.cost`, and `GET /api/usage` reports totals, days, models and sessions; pre-ledger sessions are an off-peak estimate, marked as such.
- 0.13.0 (20): runs keep going with the phone locked. While dsh has a run live, RunService (a foreground service, "dsh is working") holds a partial wake lock and keeps DSHA out of the cached-app freezer, then stops itself once /api/health shows nothing running for two checks; Settings > Screen off asks Android to exempt DSHA from battery optimisation. The chat WebView keeps its renderer at the app's priority, and if Android kills it anyway the Activity rebuilds instead of crashing. Back from more than 15 s in the background, the open session reloads from dsh's snapshot instead of patching the stream, and only the newest load may draw (overlapping loads could leave a stale transcript and a second stream).
- 0.12.0 (19): DSHA Standalone, a second build (`./build.sh standalone`, app id `dev.aum.dsha.standalone`, about 33 MB) for people without Termux. It carries Termux's Node 24 as `lib/arm64-v8a/libnode.so` with its libraries (`scripts/prepare-runtime.sh` flattens their sonames and points Node's default shell at `/system/bin/sh`) and dsh itself; a foreground service (Backend.java) unpacks dsh into the app's storage and keeps it running on 127.0.0.1:8788 behind a "dsh is running" notification. First run is just the DeepSeek key screen. Settings switches between the built-in dsh and one in Termux, restarts it, and asks for all-files access; the folder picker gains Phone storage. dsh 0.8.0: grep and glob fall back to Node when there is no ripgrep, and with DSH_STANDALONE the system prompt describes the sandbox (toybox shell, no git/python/bash, node on PATH).
- 0.11.0 (18): Live steering, Codex style. dsh 0.7.0 queues a message sent during a run instead of refusing it, and hands it to the model as a user turn at the next step boundary: after the current step's tool results, or, if the model was writing its final reply, as one more step in the same run. The app's send button stays Send while you type mid-run (Stop when the box is empty); a queued message waits under the chat with a dashed outline and a cancel button that puts the text back in the box, then becomes a normal bubble marked "Sent during the run". A stop or failure returns unread messages to the input box. The terminal client queues the same way. Subagents keep their own context; dsh reads a steer once they report back.
- 0.10.1 (17): Long runs no longer lose their start. dsh 0.6.1 trims its replay log only of finished runs, so an app reopened during a long run (every streamed token is an event, and an 18-minute run passed the 20,000 cap) replays the whole run instead of a reply's tail with no prompt. The app also reloads the session whenever a replay starts with a hole in the sequence.
