# Agent instructions — DSHA

DSHA is an Android app (`dev.aum.dsha`) plus its backend `dsh`, a DeepSeek agent harness that runs in Termux.
Several agents (Claude Code, Codex) may work here. GitHub is the shared record: `origin` = github.com/aum-unreal/dsha (**private**), branch `main`.

## Layout
- `server/` — dsh (Node 24, no npm deps). `dsh.mjs` CLI; `lib/deepseek.mjs` API client + prices; `lib/agent.mjs` loop, permission gate, event log (trimmed only of finished runs), live steering (`send()` mid-run queues; `drain()` adds the queue as one user turn after a step's tool results or instead of ending; `s.meta.steerN` marks those messages); `lib/tools.mjs`; `lib/mcp.mjs` MCP client (stdio + streamable HTTP, config `~/.dsh/mcp.json`, fakes in `server/test/fake-mcp-*.mjs`); `lib/server.mjs` HTTP/SSE API; `lib/store.mjs` ~/.dsh state. `lib/usage.mjs` the usage ledger (`~/.dsh/usage.jsonl`, one line per model call with its actual cost at that hour's rate; peak window in `isPeak()` in deepseek.mjs) and `GET /api/usage` for the app's Usage page; pre-ledger sessions are reported as an off-peak estimate, dated once in `~/.dsh/usage-est.json`. Permission gate: `allowed(name, risk, args, key, cwd)` in agent.mjs; 'edits' auto-approves built-in file writes only where `editInCwd()` (tools.mjs) says so; 'always allow' is stored under `tool.allowKey` (`mcp:<server>:<tool>` for MCP). `Runtime.repair()` answers orphaned tool_calls with a synthetic result on load/start/retry. `/api/health` returns `pid` and `boot` (the CLI notices restarts). `lib/skills.mjs` skills (SKILL.md folders: project .dsh/skills, ~/.dsh/skills, built-in server/skills, optional ~/.claude/skills) and instruction files (global ~/.dsh/DSH.md, project DSH.md/AGENTS.md/CLAUDE.md) and memory (~/.dsh/memory, MEMORY.md index in the prompt). `lib/agents.mjs` subagent definitions (Markdown in project .dsh/agents, ~/.dsh/agents, presets in `server/agents/`, optional ~/.claude/agents); the `agent` tool and the subagent loop (`Runtime.subagent`) are in `lib/agent.mjs`, and a subagent's tool events carry `parent` with ids `<agent call>/<call>`. `server/skills/` holds the built-in skills dsh-evolve and dsh-memory-evolve. `~/.local/bin/dsh` execs `server/dsh.mjs` directly, so server edits go live on `dsh restart`.
- Two builds: `./build.sh` (DSHA, talks to dsh in Termux) and `./build.sh standalone` (DSHA Standalone, `dev.aum.dsha.standalone`: Termux's node as `lib/arm64-v8a/libnode.so` from `scripts/prepare-runtime.sh` into git-ignored `runtime/`, dsh's `server/` as `assets/dsh`, `src/dev/aum/dsha/Backend.java` foreground service running it on 127.0.0.1:8788 with `DSH_STANDALONE=1`). MainActivity's `builtin()` decides which backend the UI uses; in a browser `?standalone=1` fakes the Standalone settings for `tests/ui.cjs`. Ship both APKs per version.
- `src/dev/aum/dsha/Sse.java` — SSE batching, plain Java so `tests/SseCheck.java` runs it on the JVM.
- `src/dev/aum/dsha/Policy.java` — plain-Java rules (RunService's give-up watch, share-size cap) checked on the JVM by `tests/PolicyCheck.java`. `RunService.java` — foreground service + wake lock while a run is live.
- `src/dev/aum/dsha/MainActivity.java` — main native class: WebView on `https://dsha.local/`, a `Native` bridge doing HTTP + SSE to dsh, Termux RUN_COMMAND pairing, notifications, share intent.
- Fonts: `assets/fonts/*.ttf` are fontTools Latin subsets of Nightwire's pinned OFL files (Inter, JetBrains Mono); notices appended to `assets/vendor/LICENSES.txt`. JetBrains Mono is for code, commands and paths only.
- Design: taste-skill app sheet "true-black-flat" (`.taste-skill/direction.json`). Check with `node ~/.claude/skills/design-taste-frontend/scripts/lint.mjs --app assets/` (keep 0 FAIL). No gradients, glows, uppercase labels or emoji; colour only on data and status.
- Layout modes (`relayout()` in app.js): phone, `wide` (≥680px or two side-by-side viewport segments; split at the hinge from `native.posture`), `tabletop` (hinge half-open and landscape). `tests/ui.cjs` checks all three; `?posture=wide|tabletop` forces one in a browser.
- `assets/` — the web UI (`app.js`, `app.css`, `index.html`), vendored markdown-it / DOMPurify / highlight.js in `assets/vendor/` (copied from Nightwire's pinned node_modules; notices in `LICENSES.txt`).

## Rules
- DeepSeek thinking mode: when `tools` are sent, every assistant message's `reasoning_content` must be passed back. Never strip it from stored messages. Non-API data goes in `session.meta`, never on messages.
- Tests: `tests/run.sh` (node --test for the server, the SseCheck JVM test, then `tests/ui.cjs`, a Playwright run against a real dsh with a mock model, which writes `tests/ui-*.png`). Look at the screenshots after UI changes.
- Never commit API keys, the dsh token, or `~/.dsh`. The key lives only in `~/.config/deepseek/key`.

## After every APK version is built
Bump `versionCode`/`versionName` in `AndroidManifest.xml` (and `VERSION` in `server/lib/server.mjs` when the backend changes), add a README "Changes" line, run `tests/run.sh`, `./build.sh` and `./build.sh standalone`, copy the APKs to `~/storage/shared/Download/DSHA-<ver>.apk` and `DSHA-Standalone-<ver>.apk`, then `git pull --rebase`, commit and `git push origin main`. Never force-push. Add a TOOLCHAIN.md changelog line.
